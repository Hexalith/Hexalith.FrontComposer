# Visual Baseline Change Rationale

Story 10.2 intentionally added the first committed FrontComposer specimen visual baselines for the Chromium Windows lane. Before this update, the six `frontcomposer-type-*-chromium-win32.png` files under `tests/e2e/specs/specimen-accessibility.spec.ts-snapshots/` captured the type specimen at `1296x2510`. After the current shell/specimen expansion, the accessibility-visual lane for run `28734213263` produced the same Light/Dark by Compact/Comfortable/Roomy matrix at `1296x2812` with the lower specimen content included. Reviewers should compare the before snapshots against the matching Playwright `*-actual.png` artifacts from that run and confirm the added height reflects expected rendered content rather than clipping, overlap, or hidden accessibility controls.

2026-07-06: The six Chromium Linux `frontcomposer-type-*-chromium-linux.png` baselines were updated after the framework-owned shell header action glyphs changed from accent-colored `Color.Primary` icons to neutral foreground icons. The rendered difference is limited to the header hamburger, palette, and settings glyphs in the Light/Dark by Compact/Comfortable/Roomy matrix; the update aligns the visual baseline with the neutral shell chrome contrast contract.

2026-07-09: The Chromium Linux and Windows `frontcomposer-type-*-chromium-*.png` baselines were updated after the Counter specimen host began loading the Shell scoped CSS bundle directly. Before this update, CI run `29023685860` compared the styled Windows rendering against stale unstyled `1296x2812` snapshots and failed all Light/Dark by Compact/Comfortable/Roomy variants. After this update, the Windows snapshots carry the styled runner artifact dimensions at `1280x3147`, `1280x3215`, and `1280x3283`; the Linux snapshots were regenerated from the patched host after adding specimen-scoped generated-command foreground, input, and warning-message contrast rules. The browser spec now pins the dark generated-command contrast directly and caps Windows visual drift at `76000` pixels, calibrated from the approximately `64000` changed Linux pixels caused by the post-artifact contrast fix that cannot be regenerated on a Linux workstation.

2026-09-16: Story 11.27 regenerated the six Chromium Linux baselines after the shell began rendering its banner title as `TextTag.Span` while retaining the public `Typography.AppTitle` size and weight contract. Before this update, the shell banner was the first `h1`, rendered larger than its documented `Size700` mapping, and intercepted Blazor's `FocusOnNavigate Selector="h1"` target. After the update, the banner remains visually governed by the 28 px `AppTitle` token while the type specimen's single level-one heading receives navigation focus and displays its expected focus outline. Each Light/Dark by Compact/Comfortable/Roomy comparison reported the same 13,009-pixel delta, confined to the corrected banner typography and type-specimen heading focus treatment; no content, spacing below the route heading, theme colors, or density-specific surfaces changed. These snapshots do not render generated command-route chrome; the dedicated route-contract test separately asserts focus on the generated command heading. The Windows matrix was intentionally not regenerated from the Linux workstation: its existing 76,000-pixel rasterization allowance exceeds the 13,009-pixel structural delta, and Quality run `35118098590` confirmed that the unchanged Windows baselines remain within that tolerance. This preserves platform-owned artifacts but means the Windows lane does not independently pin this smaller change; DW-1964 records the follow-up to regenerate Windows baselines and recalibrate the allowance.
