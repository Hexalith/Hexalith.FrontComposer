## Problem

`FrontComposerShortcutRegistrar.FocusFirstColumnFilterAsync` implements the legacy grid-scoped focus operation. The page-search shortcut now targets the sole enabled search on the current route through `FocusSolePageSearchAsync`.

## Common Causes

An application retains an explicit shortcut binding or direct call to `FocusFirstColumnFilterAsync` after adopting the current page-search contract.

## How To Fix

Replace the legacy shortcut handler with `FocusSolePageSearchAsync`. The replacement returns a task and delegates to the existing data-grid focus scope service. It focuses only when the current route has one enabled search target.

## Example

```csharp no-compile reason="Illustrative handler call uses the application's existing registrar instance."
await registrar.FocusSolePageSearchAsync();
```

## Suppression Guidance

A bounded adapter that deliberately preserves grid column-filter behavior may suppress HFC2122 with a documented migration deadline. Keep the suppression at the legacy call site.

## Migration/Deprecation

The diagnostic is introduced in v4.6.0, with removal targeted for v4.7.0. The legacy method continues to require focus inside the active data grid and preserves its column-filter behavior during this window. Migrate page-search bindings before the removal release.

## Related Diagnostics

This deprecation has no related diagnostic IDs. The migration page is HFC2122 itself.
