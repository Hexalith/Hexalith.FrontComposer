## Problem

Command authorization policy is invalid.

## Common Causes

The SourceTools producer emits `HFC1056` when it detects `Command authorization policy is invalid` during FrontComposer validation or runtime reporting. Inspect the diagnostic payload for the affected symbol, generated path, package, or migration record before changing code.

A command can also produce this diagnostic when an identically named attribute from another namespace hides the FrontComposer policy attribute.

A policy name that is not in Unicode Normalization Form C also produces this diagnostic, for example one written with the Kelvin sign (U+212A) instead of the letter K, or with decomposed Hangul syllables. ASP.NET Core matches policy names ordinally (ignoring case) without Unicode normalization, so such a name would never match a policy registered in the usual composed form. An accent typed as a separate combining mark fails the character rule instead, because a combining mark is not a letter or digit.

The normalization check needs ICU data on the machine that runs the compiler. Under invariant globalization (`DOTNET_SYSTEM_GLOBALIZATION_INVARIANT`) .NET reports every string as normalized, so the check is skipped there. Compatibility characters that are already normalized, such as the `ﬁ` ligature or full-width letters, are accepted; avoid them in policy names.

## How To Fix

If a name or alias points at the wrong attribute, qualify it as `Hexalith.FrontComposer.Contracts.Attributes.RequiresPolicyAttribute` or point the alias at that type.

If the message reports Unicode Normalization Form C, retype the policy name in composed form; the message shows the expected value. Normalize the host's matching `AddPolicy` registration, or the shared constant both sides use, the same way. For a combining mark, type the accented letter as one composed character.

Follow the registry-owned message template for `HFC1056` and update the affected SourceTools surface. Keep evidence project-relative and sanitized, then rerun docs validation so the help link, lifecycle state, and related diagnostics stay synchronized.

## Suppression Guidance

Suppression is `discouraged-error`. Prefer `.editorconfig` or a narrowly scoped pragma for analyzer diagnostics, and record migration or architecture rationale for Error-level suppressions.

## Migration/Deprecation

Since DW-877, a policy name outside Unicode Normalization Form C fails with this diagnostic, and `RequiresPolicyAttribute` throws for it when reflected. Commands that compiled with such a name before now need the composed name, both in the attribute and in the host policy registration.
