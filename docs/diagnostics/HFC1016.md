## Problem

Every FrontComposer command property that can participate in generated assignment must declare a public, non-init setter. This uniform command-shape policy includes user-entered properties and derivable properties discovered by convention, inheritance, or `[DerivedFrom]`.

## Common Causes

`HFC1016` is emitted when a command property has no setter, an `init` accessor, or a setter that is not public. Positional records commonly produce init-only properties. The same rule applies to derivable properties even when their type uses a safe, type-free provider fall-through arm.

## How To Fix

Change the affected property to a normal public setter:

```csharp no-compile reason="Illustrative command property declaration omits its containing command type and package references."
public string MessageId { get; set; } = string.Empty;
```

Do not add `[DerivedFrom]` as a setter workaround; derivable properties follow the same setter rule.

## Example

```text
HFC1016: [Command] type 'ApproveOrder' property 'MessageId' has no setter. FrontComposer command generation requires every command property to declare a public non-init setter. Change the property to '{ get; set; }'.
```

## Suppression Guidance

Suppression is `discouraged-error`. Suppression cannot restore generation: it may hide `HFC1016`, but the invalid command model remains rejected and no renderer or other command artifacts are emitted. Fix the setter instead of suppressing the error.

## Migration/Deprecation

Breaking derivable-setter migration: commands whose derivable properties previously used getter-only, private-set, or init-only shapes must change those properties to public `{ get; set; }`. Reflection-based prefill no longer exempts derivable setters from the uniform generated-command shape.
