# FrontComposer 9.1 to 9.2 Migration

Use this guide when a project still registers the development overlay with the old debug-overlay API or when a shipped skill-corpus example touches customization-sensitive startup code.

## Affected Versions

The change applies to adopters moving from the 9.1 development overlay contract to the 9.2 developer-mode contract. The affected package surface is the Shell startup registration path and examples that teach local diagnostics or generated-output debugging.

## Why This Changed

The versioned CLI migration contract aligned inspect/migrate output with the developer-mode overlay name used by the rest of the framework. The old debug-overlay name made diagnostics, generated-output docs, and skill-corpus examples describe the same feature with different labels.

## Old Code

```csharp no-compile reason="Shows obsolete startup API that may not exist in the current package."
using Microsoft.Extensions.DependencyInjection;

namespace Acme.Orders;

public static class FrontComposerStartup
{
    public static IServiceCollection AddOrdersFrontComposer(this IServiceCollection services)
    {
        return services.AddFrontComposerDebugOverlay();
    }
}
```

## New Code

```csharp no-compile reason="Startup extension availability depends on the adopter host package reference."
using Microsoft.Extensions.DependencyInjection;

namespace Acme.Orders;

public static class FrontComposerStartup
{
    public static IServiceCollection AddOrdersFrontComposer(this IServiceCollection services)
    {
        return services.AddFrontComposerDevMode();
    }
}
```

## Analyzer And Code Fix

This `cli-supported` edge is exactly `9.1.0` to `9.2.0`. The CLI's private scanner emits
`HFCM9001` for `IdentifierNameSyntax` nodes named `AddFrontComposerDebugOverlay`, excluding
identifiers inside `nameof`. Its CLI-only safe fix is an allowlisted syntactic rename to
`AddFrontComposerDevMode`, not semantic validation of symbol identity or behavior. It can also
rename same-named non-API identifiers, including variable references and method groups.
Review the diff before applying it; the safe-fix classification does not prove the rename is
semantically safe. No IDE analyzer/code fix is published for this migration
(`codeFixAvailable: false` describes that IDE availability). Any `HFCM9002` evidence stays manual-only.

For customization diagnostics, follow the [Customization prerequisites](../reference/components/customization.md)
and [customization cookbook](../how-to/customization-gradient-cookbook.md). The Shell assembly itself
must be compiled with `DEBUG`, and DI must contain an `IHostEnvironment` explicitly identifying
Development. Register logging and the environment before `AddFrontComposerDevMode()`; the
parameterless overload recognizes instance/factory environment registrations, or use the explicit
environment overload while keeping `IHostEnvironment` registered in DI. The published Release
NuGet package does not emit these customization diagnostics/panels, even for a Debug adopter in
Development.

Preview first; dry-run is the default and writes no source:

```shell
dotnet tool run frontcomposer migrate --project Acme.Orders.csproj --from 9.1.0 --to 9.2.0 --dry-run
```

After reviewing the report, rerun the same command with `--apply` in place of `--dry-run`.
Apply atomically replaces each eligible file; earlier writes remain if a later write fails.
See [migration guidance](../how-to/migration-guides.md) for exclusions and partial failures.

## Skill Corpus Evidence

Story 8-5 skill-corpus examples are part of the migration trigger. Any example that still shows `AddFrontComposerDebugOverlay` must be updated with the same wording as this guide or recorded with non-breaking evidence in the docs validation manifest. The expected current term is `AddFrontComposerDevMode`.

## HFCM9001

What: a syntactic obsolete-name identifier match, which may also refer to a non-API identifier.

Expected: `AddFrontComposerDevMode`.

Got: `AddFrontComposerDebugOverlay`.

Fix: replace the obsolete API with `AddFrontComposerDevMode`, then rerun `dotnet tool run frontcomposer migrate --project Acme.Orders.csproj --from 9.1.0 --to 9.2.0 --dry-run` and docs validation.

## HFCM9002

`HFCM9002` is synthetic/manual-only. Production emission is not approved; normal adopter builds
do not produce production SourceTools `HFCM9002` sidecars. Hand-crafted `*.diagnostics.json`
evidence under `obj/{Configuration}/{TargetFramework}/generated/HexalithFrontComposer/` can
exercise the manual review contract. This is not an executable fix or an additional version edge.

What: customization-sensitive migration marker.

Expected: developer review before changing behavior.

Fix: review the affected call site manually and keep at least one minor version of deprecation notice before removal.
