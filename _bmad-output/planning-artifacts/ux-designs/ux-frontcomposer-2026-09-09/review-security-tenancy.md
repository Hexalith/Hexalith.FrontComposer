# Security and Tenancy Review — Hexalith Common Application UX

## Overall verdict

**Needs revision before security-sensitive UX handoff.** The spine pair has a strong fail-closed foundation for tenant-scoped human surfaces, two-layer command authorization, controlled-field injection, support-safe output, fresh-row isolation, and explicit MCP failure shapes. It is not yet an independently implementable or testable security contract: known MCP disclosure/oracle risks are not carried as finalization blockers, the cross-request lifecycle store has no explicit caller/tenant binding, user/auth scope loss is weaker than tenant loss, and UJ-6 does not prove the security guarantees asserted by UJ-2 through UJ-4.

Finding counts: **Critical 0 · High 4 · Medium 5 · Low 2**.

## Strengths

- The governing posture is clear: every human surface is tenant/user scoped, missing or stale tenant context is explicit rather than empty-looking, and every agent surface is expected to sit behind host authentication (`EXPERIENCE.md:26-28`).
- Scope resolution is required before projection, subscription, count, preference, pending-state, and fresh-row reads; old scope must clear before new scope renders; storage has tenant/user/feature partitioning and no default tenant (`EXPERIENCE.md:253-260`).
- Authorization is deliberately two-layered. Protected UI resolves Pending/Authorized/NotAuthorized, policy is evaluated before and after `BeforeSubmit`, and the service boundary authorizes again (`EXPERIENCE.md:110-111, 169-173, 257-258`).
- Controlled/derived fields are hidden from generated forms and injected server-side, while UJ-4 places schema negotiation and argument validation before MCP command execution (`EXPERIENCE.md:110, 257, 320-329`).
- Support-safety is broad: user-facing rejection copy is structured, diagnostics are development-only, and UI/MCP/log/telemetry/snapshot/evidence surfaces exclude raw tokens, JWT payloads, EventStore metadata, raw payloads, stack traces, unrestricted PII, and hidden tool/resource identifiers (`EXPERIENCE.md:74-87, 115, 140-148, 210, 253-260, 348-351`; `DESIGN.md:140`).
- Fresh-row identity and scope handling are unusually precise: identity is captured before dispatch, materiality is independent, unsafe outcomes are suppressed, reads/renders are tenant/user/lane scoped, and active rows use atomic first-wins identity (`EXPERIENCE.md:189-195`).
- The MCP matrix does not overclaim total opacity: it explicitly records the empty-list credential signal, static resource-catalog disclosure, registered-hidden versus unregistered-resource distinction, and schema classes that permit or block side effects (`EXPERIENCE.md:197-210`).

## Findings

### Critical

None.

### High

1. **Known MCP disclosure and enforcement gaps are described, but not made finalization blockers.** The matrix records that unauthenticated/missing-tenant `tools/list` returns an empty list that acts as a credential-validity signal, `resources/list` discloses every generated projection/skill descriptor to every caller, and unregistered resource URIs remain distinguishable from registered hidden resources (`EXPERIENCE.md:197-208`). The security section names the non-Development `AllowAll*` enforcement gap (`EXPERIENCE.md:253-260`), yet the closing Open Questions omit the independent leak/oracle disposition, endpoint-authentication enforcement evidence, and allow-all ban required before this risk is accepted (`EXPERIENCE.md:353-358`). UJ-4 consequently reads as a settled secure deployment even though the draft itself contains unresolved disclosure behavior (`EXPERIENCE.md:320-329`). *Fix:* add a security-gate item that prevents `status: final` until the independent MCP disclosure/oracle disposition and the endpoint-authentication/non-Development-allow-all enforcement evidence are linked. Enumerate the intentionally accepted residuals separately from gaps still requiring implementation.

2. **The singleton MCP lifecycle store is not explicitly isolated by the original caller and tenant.** The contract says lifecycle crosses requests through singleton state with a scoped tracker, but it does not define the partition key, require every later poll to re-resolve and re-authorize the original caller/tenant binding, or state what happens after tenant change, sign-out, or credential rotation (`EXPERIENCE.md:210, 253-260`). UJ-4 only says the agent polls in a later DI scope and obtains a terminal snapshot without tenant internals (`EXPERIENCE.md:325-329`). A globally indexed correlation/message identifier would satisfy that prose while leaking lifecycle state across callers. *Fix:* bind lifecycle entries to the exact authenticated-caller/tenant scope plus command identity required by the runtime contract; re-run admission on every subscribe/poll; reject old-scope lookup with the opaque `unknown_tool` shape; define expiry/eviction and scope-change behavior; and add a two-caller/two-tenant cross-request negative test.

3. **Missing/stale user or authentication context is not given the same fail-closed transition contract as missing/stale tenant context.** The Foundation says all human surfaces are tenant- and user-scoped, but the explicit blocking state and UJ-2 failure cover only tenant absence/staleness (`EXPERIENCE.md:26-28, 127-132, 295-306`). Account states mention token eviction and a stable route, but not session expiry during an active projection/command, clearing rendered rows/counts/pending lifecycle/fresh markers before navigation, or re-authentication through a validated return path (`EXPERIENCE.md:97, 130, 142, 253-260`). *Fix:* define a combined stale/missing tenant-user-auth transition sequence: stop dispatch/subscriptions, invalidate old groups/tokens, clear scoped rendered and cached state before replacement, present a support-safe blocked or re-authentication state, validate the return path, and only then admit the new scope. Add mid-grid and mid-command session-expiry/sign-out cases.

4. **UJ-6 cannot verify the security promises made by UJ-2, UJ-3, and UJ-4.** Its configured scenarios include generic authorization denial and its assertions mention fresh-row scope/first-wins plus evidence redaction, but it does not require tenant/user transition tests, sign-out/token eviction, storage-key isolation, service-boundary reauthorization, controlled-field tampering, MCP hidden-vs-absent equality, list/read oracles, schema-admission no-side-effect behavior, cross-request lifecycle isolation, endpoint authentication, or the production allow-all ban (`EXPERIENCE.md:342-351`). *Fix:* expand the verification journey into named human-shell and MCP/Governance evidence lanes. Require exact negative matrices for two users/two tenants, scope changes before the next producer mutation, sign-out/session expiry, direct-route and post-`BeforeSubmit` authorization denial, injected-field override attempts, every MCP disclosure row, and cross-scope lifecycle polling.

### Medium

1. **UJ-3 has no authorization-denial or authorization-revocation failure path.** Its successful path moves Pending to Authorized, and its only failure is a domain Rejected outcome after dispatch (`EXPERIENCE.md:308-318`). That does not exercise NotAuthorized before form reveal or the second service-boundary/policy decision after `BeforeSubmit`, despite those being explicit component and state contracts (`EXPERIENCE.md:111, 144, 169-173, 257-258`). *Fix:* add failures for initial denial, direct-route denial, and policy loss or command mutation between initial admission and dispatch; each must reveal no protected form/data, cause no dispatch, retain safe focus/input only where allowed, and expose support-safe recovery. Bind each to UJ-6 evidence.

2. **Controlled-field injection does not define hostile-input behavior precisely enough.** The form and security prose say controlled/derived fields are hidden and injected later, and UJ-4 places injection after validation (`EXPERIENCE.md:110, 253-258, 320-326`). It never explicitly requires MCP schemas to omit those fields, rejects a caller-supplied duplicate before any side effect, or guarantees that client input cannot override server values. *Fix:* state that controlled fields are absent from public input schemas and editable UI, supplied copies are rejected before instantiation/dispatch under a support-safe public category, and server values are derived only after auth/tenant admission and schema/argument validation. Add tampering tests for TenantId, UserId, MessageId, CorrelationId, timestamps, and declared derived values.

3. **Storage isolation lacks the canonicalization and collision contract needed to make the scoped key claim safe.** Settings and security specify tenant/user scoping and skip-on-missing behavior, but they do not name one canonical scope resolver/key builder or cover whitespace, colon, Unicode normalization, and mixed-case identity collisions (`EXPERIENCE.md:100, 132, 141, 255-256`). *Fix:* require every persisted shell feature to use the single canonical storage-scope resolver/key builder, reject ambiguous or missing scope, and add cross-feature/cross-user/cross-tenant collision properties for whitespace, delimiter, NFC/NFD, and case normalization.

4. **The MCP gate boundary is internally ambiguous for unauthenticated and skill-resource traffic.** Foundation and UJ-4 require host authentication, while the matrix defines an unauthenticated `tools/list` handler result (`EXPERIENCE.md:28, 201, 320-324`); the security section says MCP requires both tenant-tool and resource-visibility gates, while the skill row only calls skills global validated content and does not state whether visibility gating is intentionally bypassed (`EXPERIENCE.md:208, 253-260`). *Fix:* distinguish transport/endpoint authentication from defense-in-depth handler behavior, and distinguish mandatory gate registration/startup validation from per-request admission. Explicitly state that skill resources are framework-global validated content and whether they bypass the projection visibility gate; keep that exception narrow and test its no-tenant-data invariant.

5. **The fresh-row implementation contract is stronger than its journey and test wording.** State behavior says prior-scope entries are rejected before read/render, but UJ-2 only shows a correctly scoped marker and UJ-6 says “scope/first-wins behavior” without naming the adversarial transition (`EXPERIENCE.md:189-195, 295-306, 342-348`). *Fix:* make UJ-2 cover a tenant/user switch while a marker is active, with removal before `Snapshot`/DOM render and no need for a subsequent add; make UJ-6 test already-rendered DOM invalidation, concurrent transition/add, old-scope read, dismiss/expiry, and first-wins provenance across two identities.

### Low

1. **The source-stated MCP timing non-goal is absent, making the opacity promise easy to overread.** The matrix correctly limits hidden-vs-absent byte equality to the same caller, but the spine never says evaluation-time side channels have no bound (`EXPERIENCE.md:197-210, 329`). *Fix:* add the timing-side-channel exclusion next to the disclosure matrix so consumers do not interpret byte-identical response shapes as a timing-isolation guarantee.

2. **Security-consequential microcopy remains unresolved.** The draft defers final language for missing tenant, NeedsReview, Warning, and Degraded states (`DESIGN.md:154-158`; `EXPERIENCE.md:87, 353-358`), although these messages decide whether operators can distinguish denied/stale/unconfirmed states without leaking internal detail. *Fix:* approve localized message keys and support-safe fields for each consequential state, including stable error/docs codes and recovery actions; test that interpolation cannot include tenant/user values, raw paths, payloads, claims, or exception text.

## Journey security and testability

- **UJ-2 — partially testable.** Projection-health, tenant failure, and a positive scoped fresh-row outcome are explicit (`EXPERIENCE.md:295-306`). It lacks user/session loss, active-scope transition, stale subscription/group eviction, and old-scope marker negative cases.
- **UJ-3 — partially testable.** Editable-field rendering, lifecycle truth, concurrency, and support-safe Rejected recovery are concrete (`EXPERIENCE.md:308-318`). It lacks initial/direct-route denial, post-`BeforeSubmit` reauthorization failure, controlled-field override attempts, and sign-out/scope loss while an operation is active.
- **UJ-4 — protocol-testable but not security-complete.** It orders auth, gates, admission, schema negotiation, validation, injection, and cross-request polling and gives opaque failure outcomes (`EXPERIENCE.md:320-329`). It does not bind later lifecycle reads to the originating caller/tenant, distinguish endpoint auth from handler fallback, or carry the unresolved catalog/oracle acceptance gate.
- **UJ-6 — insufficient as the closure journey.** It provides a useful bUnit baseline and strong redaction intent (`EXPERIENCE.md:342-351`), but a separate named MCP/Governance lane and explicit cross-scope/account/storage cases are required to verify the above guarantees.

## Residual risks

- The static resource catalog deliberately exposes bounded-context and projection names; empty `tools/list` reveals an authentication/tenant validity distinction; registered-hidden and unregistered resource reads remain distinguishable. These are documented behaviors, not accepted residual risks, until independent security disposition is recorded (`EXPERIENCE.md:197-208`).
- Non-Development `AllowAll*` gate enforcement remains an acknowledged readiness gap (`EXPERIENCE.md:259`). Endpoint authentication is adopter-owned in UJ-4 and needs enforcement evidence rather than prose alone (`EXPERIENCE.md:320-324`).
- A cross-request singleton lifecycle store increases the impact of any missing partition or admission check (`EXPERIENCE.md:210`).
- Server-allocated target keys intentionally receive no automatic fresh-row marker; this is safer than guessing but leaves a known operator-observability limitation (`EXPERIENCE.md:191-193, 279, 303`).
- Timing side channels remain outside the source milestone even after response-shape issues are resolved; the spine should declare that boundary.

## Verification gaps

- This is a contract review. No runtime traces, DOM/state captures, storage contents, SignalR group observations, token-store observations, MCP wire bytes, timing measurements, or side-effect probes were executed.
- The draft does not link candidate-bound evidence for tenant/user scope clearing, stale-group blocking, sign-out/token eviction, canonical storage-key equivalence, controlled-field tampering, or cross-request lifecycle isolation.
- The independent MCP leak/oracle suite and acceptance disposition are not represented as completed evidence in the spine; the known catalog, credential-signal, SDK-not-found, endpoint-authentication, and allow-all cases therefore remain open.
- UJ-6 names redaction categories but not hostile vectors in property names/dictionary keys, punctuation-heavy secrets, oversized payloads, or raw local/external paths (`EXPERIENCE.md:344-351`).
- No journey proves that a scope change clears an already-rendered projection, home/count cache, preference hydration, pending lifecycle state, and fresh-row state before any new-scope render.
