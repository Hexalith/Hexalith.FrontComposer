Flow coverage

adequate

Both experience documents contain all six PRD journey titles in order, with the named people, numbered steps, a climax and a failure path. Each journey has a surface. One recovery instruction contradicts the implementation.

High

F1 · A failed optional retry can be mistaken for a degraded command

UJ-3 says a second failure degrades the command. Once the service has acknowledged the original MessageId, a failed retry to recover unreadable correlation data still returns Accepted with that ID and unknown correlation. The example could lead an operator to treat accepted work as degraded prematurely.

Suggested fix. Correct the UJ-3 failure path. Keep the accepted outcome after this retry and identify the later lifecycle evidence or confirmation deadline that can move the command to Degraded.

Accessibility

review-accessibility.md

The responsive navigation preview hides keyboard focus in two reproducible interactions. The review also reproduced both focus destinations noted in the rubric. The offline lifecycle selector retained focus through all ten snapshots.

High

A1 · Keyboard focus moves behind the open navigation drawer

In the navigation mockup at 320 and 1024 CSS px, Tab can move past the drawer into workspace links that the drawer fully covers. Escape leaves the drawer open. The active control is hidden in this sequence (WCAG 2.2 SC 2.4.11).

Suggested fix. Keep a disclosure in document flow, or give the overlay modal keyboard behavior with inert background controls. Support dismissal with focus return and verify forward and reverse Tab.

Drawer styles and controls · Canonical UX-AE-1

High

A2 · Current navigation items lose visible focus in forced colors

At desktop width, the mockup paints the same outline on a current Module link or workspace link before and after keyboard focus. A pixel comparison showed a visible focus change on an inactive link only (WCAG SC 2.4.7).

Suggested fix. Give current items a distinct forced-colors focus outline and offset. Test the current, focused and current-plus-focused states on both controls.

Navigation style rules · Visual focus contract

Medium

A3 · Module navigation focuses the preview frame

Enter on Parties in the navigation mockup changes route but focuses the outer section containing the shell and address bar. FM-01 sends focus to the new route heading.

Suggested fix. Move focus to the destination workspace heading on Module activation, or mark the fragment interaction as a layout preview and identify the product focus destination alongside it.

Module links and destinations, lines 136–202 · FM-01

Medium

A4 · The Module Tab selector behaves as ordinary links

Right Arrow on the active workspace tab has no effect. Enter on Users focuses the destination section. The mockup omits tab roles, selection and panel relationships. FM-02 retains focus on the selected tab.

Suggested fix. Implement arrow-key navigation and selected-tab focus with a labelled panel, or explicitly identify the route links as a preview and link the tab interaction contract.

Workspace selector, lines 151–153 and 177–179 · FM-02

Fluent UI implementation alignment

review-fluent-ui-v5.md

The most consequential gap is the empty drawer in the default narrow shell. Two additional findings affect status readability and the Settings density contract. The lifecycle mockup also differs from the account control.

High

FL-1 · Phone and tablet navigation has no Module list in the default drawer

The default shell removes its only navigation area below 1024 CSS px. Its hamburger supplies a title but no child content. Fluent UI 5.1.0 falls back to the registered navigation area, which is absent on these tiers. In a local build of Counter.Web, at 320 CSS px the opened drawer contained only its title and Close button, including after a resize from 1440. At 900 CSS px neither Enter nor a click produced a visible dialog or a Module list. Counter was available on Home at both widths and the desktop rail reached /counter/counter-projection.

Suggested fix. Pass the authorized Module list to the active drawer exactly once. Cover cold phone and tablet entry plus a desktop-to-phone resize. Open the drawer by keyboard, activate Counter and verify its default tab, route heading and current entry.

Responsive specification · Shell composition · Viewport guard · Hamburger · Responsive sidebar tests · Named-drawer and focus tests · Navigation mockup

Medium

FL-2 · Generated status cells hide the visible label until interaction

UX-DR2 requires persistent icon-plus-text status. An annotated enum cell renders an FcStatusIcon with an accessible name, but its localized label is in the tooltip. A sighted reader must hover or focus to read it.

Suggested fix. Render persistent text next to the glyph in the generated presentation, preserve the accessible name and check the cell at rest and in forced colors.

UX-DR2 · PRD · Generated column · FcStatusIcon · Component tests

Medium

FL-3 · Settings omits the difference between selected and effective density

The working pair implies that every choice updates the page and that Settings stays silent. Phone and Tablet force Comfortable even when Compact is saved. Initial hydration and opening Settings are silent. A later effective density change can announce the new value once.

Suggested fix. Document the narrow-viewport override, the saved choice and preview, and the announcement trigger in Settings and the responsive guidance.

Working component and state patterns · Density precedence · Settings dialog · Density announcer · Forced-density tests

Low

FL-4 · The lifecycle preview exposes the name in the closed header

The closed lifecycle mockup header displays “Marc”. The working contract and account component show an avatar in the closed header and the display name inside the account menu.

Suggested fix. Use the same closed avatar treatment as the responsive mockup.

Lifecycle mockup · Design components · Account menu
