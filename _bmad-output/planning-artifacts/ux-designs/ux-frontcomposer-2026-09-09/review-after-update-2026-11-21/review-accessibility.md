# Accessibility review after the UX update

On 2026-11-21, all four navigation findings passed their keyboard and visual rechecks in the standalone reference. Three issues found during this pass also passed after correction: cold deep-link focus, feedback for an unavailable tab, and naming of the decorative lifecycle rail. The default shell’s narrow-screen Module navigation and generated enum status labels still require the product fixes recorded in the Fluent review. ## Corrections verified during this review

- **Cold links and reloads.** Chromium initially moved focus to the fragment-matched panel after the script focused the heading. The enhanced panels now use IDs separate from the route fragments. Opening or reloading `#tenants/workspace-users` or `#parties/overview` focused the appropriate `h1` and exposed the requested tab and panel. [Navigation reference](../mockups/key-responsive-navigation.html)
- **Unavailable tabs.** A bare `#tenants` selected Tenants silently. An explicit `#tenants/unavailable` selected the same tab and added “That page is unavailable. Showing Tenants.” to the polite atomic status node once. Reapplying the same fragment added no message. Valid navigation cleared the status. A fresh invalid Parties attempt announced Overview. Back and Forward preserved the distinction between a valid route and a new fallback attempt. [Navigation reference](../mockups/key-responsive-navigation.html) · [Announcement matrix](../../../ux-design.md#ux-am-1---announcement-matrix)
- **Decorative lifecycle rail.** The illustrated rail previously supplied a name on a generic container. It is now hidden from assistive technology and contains no focusable controls. The state selector, Account disclosure, Counter heading, and command status remain exposed. [Lifecycle reference](../mockups/key-command-lifecycle.html)
