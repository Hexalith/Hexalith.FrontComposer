## Detail per finding

### SU-1 (High) — the compensating control does not exist

The Deferred entry is the right place to accept S-1, and the wording is candid about what is not delayed-activated. But it borrows its safety from "branch protection and required review of policy, `eng/*.py`, and the three workflows", and the live repository has none of that: `GET /branches/main` returns `protected: false`, the classic protection endpoint returns 404, `GET /rulesets` is empty, and there is no `CODEOWNERS`. With a non-admin `write` collaborator present, the practical control today is the Release Owner's diff review before clicking `production` — a real control, but a human one, and not the one the spine names. The `production` gate itself holds (reviewer list = Release Owner, admins cannot bypass, branch policy `main` only), which is why this is High and not Critical: the lone write collaborator still cannot publish; they can only present a candidate whose evaluator code they wrote. Restate the acceptance honestly or create the control; either way, record the live protection state in the ledger so future drift is visible.

### SU-2 (Medium) — second checkout into the Builds execution path

Verified in `_builds_execution_commit_for_caller`: matches are collected with a regex that requires the literal `Hexalith/Hexalith.Builds` repository and a 40-hex ref, then de-duplicated by commit. A later step `uses: actions/checkout@<pinned>` with `repository: Hexalith/Hexalith.Builds`, `ref: main`, `path: .hexalith/builds-execution` is invisible to the regex and, at runtime, replaces the directory before `./.hexalith/builds-execution/Github/initialize-build` runs. The spine's rule text permits the same reading. The mitigation is real but indirect (the caller blob hash must already be in the active policy), so the fix is to make the rule count every write into the path and to state the residual.

### SU-3 / SU-4 (Medium) — AD-18's evidentiary claims need a schema and a verifier

AD-18 is the correct answer to S-2/S-3 on the authorization question. Its two evidentiary claims — actors are recorded, and Governance asserts the environment gate statically — are not yet realizable: the closed AD-15 shape has no actor member, approval identity is API-only, and environment protection is configuration, not a blob. Both are fixable inside the existing pattern (closed schema bump with atomic fixtures; read-only API capture in the post-release verifier).

### SU-5 (Medium) — per-run approval digest

This is a property, not a defect: binding the CI handoff hash into the approval digest means an approval cannot be reused across candidates, which is stronger than the 2026-07-19 design. But it must be stated, together with the capture ordering, or the next implementer will "fix" the operator burden the way 4.1.1 did. The live state (no `RELEASE_ATTESTATION_*` variables, `bind_live_fallback_digest=True` in production classify, variable not passed by `release.yml`) confirms the A-1 nonconformance is still open; the spine text itself closes the drift path correctly.

## Confirmed sound — trust invariants the rewrite gets right

1. **Closed-world identity and acquisition (AD-3, AD-10):** identity is the trust key, gitlink path is evidence, `local_path` is acquisition data; remotes reconstructed from canonical identity, never candidate text; content-address trust with TLS as availability; `sslVerify=false`, credential helpers, and protocol widening forbidden.
2. **Exact-object provenance and canonicalization (AD-2, AD-4, AD-5):** committed objects only; strict 40-hex/64-hex; closed envelope with duplicate-member rejection; project canonicalization v1 pinned by a golden digest; SHA-1 object format required with the collision acceptance stated in Deferred.
3. **No candidate-controlled execution (AD-8, Conventions):** argv arrays only from the active policy; `merge_base == event_base` fail-closed; candidate is the CI-built merge SHA; nested submodules never initialized; contract-tree materialization rejects symlinks/gitlinks/special modes with ceilings measured before decode.
4. **Delayed activation of declarative trust (AD-12):** policy read from `event_base`/`before`/handoff-recorded commit; a policy change cannot authorize itself; zero-before cannot select trust and is never release-eligible; malformed active policy fails closed with no bootstrap reachable; two-phase pre-authorized closure switching; an absent closure is a gate failure, never a soft deferral.
5. **Evaluator trust by exact caller blob (AD-13, AD-16):** caller blob SHA-256 must match one active-policy row; the caller blob literally names the reusable commit which fixes every transitive action; `@main` anywhere in the closure is non-conforming; Builds execution lineage rooted at the owner-accepted `a8a50859` and advanced only by pre-authorized closures. Verified live: `release.yml` blob → `4eb33928` row authorized 2026-09-05 (`05f77621`).
6. **Exact-candidate propagation (AD-13, AD-15):** authenticated handoff candidate is the sole authority; `main` re-validated before protected credentials; the post-release hop derives the live root only from the handoff candidate and sealed manifest, never `workflow_run.head_sha`/`GITHUB_SHA`/tag; race fixture and pre-manifest failure fixture required; `hexalith.dependency-release-source.v1` explicitly demoted to diagnostic.
7. **Handoff authentication (AD-13, AD-15, AD-18):** names embed run coordinates; exactly one non-expired match; zip shape and unsafe-path rejection; recorded coordinates must equal authenticated ones; producing step is the only permitted uploader; name conflict is fatal; a Builds job in the same CI run pre-uploading the name causes the trusted upload to fail and the run to fail (verified in `ci.yml` ordering: `dependency-governance` `needs: ci`).
8. **Least privilege as implemented (AD-18):** workflow-level `contents: read` in all three workflows; `actions: read` only where the API is read; no `actions: write`, no `pull_request_target`; `dependency-governance`, `verify-source`, `plan-release`, `verify-publication`, and `emit-verification-handoff` are secretless; the only write-scoped job is the reusable call, whose callee binds `environment: ${{ inputs.environment-name }}` on both `release` and `governed-release`.
9. **Fail-closed evidence (AD-9, AD-14, AD-15, AD-17):** `publish_authorized=false` before side effects; post-publication verification never authorizes; v2 manifests verify-only and never fallback-eligible; legacy audit-only; seal covers every top-level member except `seal`; `definition_digest` recomputed offline; deferred-emission cannot green after publication (`release.yml` `emit-verification-handoff` exits 1 when `publication_attempted`).
10. **Governance on the release path:** `release_prepublish.py prepare` runs the `Category=Governance` lane on the candidate inside `prepare-candidate` (only `GovernanceBuild`, `Performance`, `e2e-palette`, `NightlyProperty`, `Quarantined` excluded), so AD-18's static assertions execute before sealing even though `quality.yml` is not an AD-13-authenticated input — from candidate code, i.e. inside the S-1 acceptance.
