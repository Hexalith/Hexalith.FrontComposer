# Reviewer Gate — Security / Supply-Chain Trust Boundary Lens (VALIDATE)

- **Object:** `ARCHITECTURE-SPINE.md` — GOV-1 dependency provenance, current working-tree version, `AD-1` through `AD-18`
- **Date:** 2026-09-09
- **Intent:** validate only; neither the spine nor implementation was changed
- **Focus:** publication authority, actor/environment controls, candidate-controlled code, mutable references, fallback approvals, artifact authenticity, privilege scope, and revocation/incident handling
- **Implementation baseline:** repository `HEAD 053b2008`; exact release reusable pinned by the caller at Hexalith.Builds `4eb33928a1d8c7775f97221cf9edc171db0cb5f8`

## Verdict

**FAIL — architecture update required before this can be treated as a safe publication contract.** The spine has one Critical contradiction: `AD-18` says it prevents a write-scoped job from consuming candidate code, but its Rule does not require a build/publish privilege split, and both the legacy and proposed governed reusable paths execute candidate-controlled programs in the same job that holds publication scopes and secrets. A malicious merged project/build/release script can therefore act with `contents: write`, `NUGET_API_KEY`, signing material, and attestation/OIDC authority after one environment approval.

The live `production` environment remains a meaningful human authorization barrier, so no route was found for the current non-admin write collaborator to publish *without* a Release Owner approval. That control does not make executing the candidate with release credentials safe. The post-release ledger also executes unpinned helper code from the then-current default branch before checking out the released candidate, allowing a later direct push to suppress incident detection. Finally, the checked-in caller explicitly selects the legacy reusable path rather than the BUILD-REL-1 governed contract assumed by the spine.

**New-finding counts:** Critical 1 · High 2 · Medium 1 · Low 0. The existing `NC-1` through `NC-30` implementation register remains separate and is not recounted here.

## Reconciliation with the implementation nonconformance register

The register is correctly framed: its rows are implementation drift, not evidence that the corresponding architecture rules are defective. This review does not duplicate those rows.

- **Fallback authority remains acknowledged, not new:** `NC-1`–`NC-3` cover live rebinding, the missing immutable operator digest input, and the missing production-path mutation fixtures. The current repository has no `RELEASE_ATTESTATION_*` variables, so the incomplete fallback blocks today; if the other fallback fields are later populated while `bind_live_fallback_digest=True` remains, `NC-1` can self-satisfy the approval digest. AD-9 itself is appropriately fail-closed and run-bound (`ARCHITECTURE-SPINE.md:202-234`).
- **Evaluator and mutable-reference drift remains acknowledged:** `NC-4`–`NC-8`, `NC-13`, `NC-16`–`NC-18`, `NC-20`–`NC-22`, `NC-28`, and `NC-30` cover soft deferrals, nullable post-release rows, static assertions, stale lineage, quality-run selection, closure reconstruction, mutable path injection, and missing lineage verification. `SEC-VAL-02` is additional: it concerns executable post-release helpers, not only the caller/action closure.
- **Artifact/ledger drift remains acknowledged:** `NC-5`, `NC-6`, `NC-9`, `NC-10`, `NC-12`, `NC-19`, `NC-26`, and `NC-29` cover independent CI-artifact authentication, handoff v2 shape, publication-started semantics, actors/environment evidence, and ledger closure. The spine’s artifact-coordinate and independent-download model is sound once these are implemented.
- **Live repository governance remains explicitly acknowledged:** `NC-27` and Deferred accurately record no branch protection/ruleset, no `CODEOWNERS`, and a non-admin write collaborator. The 2026-09-09 API read confirmed two admins plus one write collaborator, no repository ruleset/classic `main` protection, and `production` restricted to branch `main` with one required reviewer and `prevent_self_review=false`. This is not silently promoted to a spine defect here; it materially amplifies SEC-VAL-01 and SEC-VAL-02.
- **Register gap:** only SEC-VAL-03 is a present, directly evidenced implementation mismatch not already represented. Any implementation rows created for SEC-VAL-01/02 should follow the architecture update so they target the corrected contract.

## Confirmed sound

1. **Publication actor barrier:** `workflow_dispatch` is checked against `refs/heads/main`, the dispatched SHA is compared with a live API read of `main`, and the selected CI run is matched by exact head/run coordinates before protected work (`.github/workflows/release.yml:41-76`, `:78-147`). The live `production` environment has branch `main` as its only deployment branch and one required reviewer. A non-admin writer cannot publish alone.
2. **Least privilege outside publication:** graph collection and pre-publication authentication use read-only contents/actions permissions and do not receive release secrets (`.github/workflows/ci.yml:20-55`; `.github/workflows/release.yml:21-39`). No GOV-1 workflow grants `actions: write`.
3. **Mutable references are kept outside the intended trust chain:** the authenticated CI and Release callers pin their reusable/action references to 40-hex commits (`.github/workflows/ci.yml:20-25`, `:52-55`; `.github/workflows/release.yml:33-39`, `:229-239`, `:321-329`). `quality.yml` still uses `@main`, but AD-13 correctly classifies it as a deny-only precondition with no evidentiary weight (`ARCHITECTURE-SPINE.md:319-329`); this remains an implementation matter under `NC-18`/`NC-28`, not a publication-authority bypass by itself.
4. **Artifact coordinates and extraction:** CI handoff artifacts are named with run ID/attempt and uploaded with `if-no-files-found: error` (`.github/workflows/ci.yml:211-227`); Release requires exactly one non-expired matching artifact and a single safe archive member before live verification (`.github/workflows/release.yml:78-145`). The handoff design independently re-downloads the CI artifact and compares hashes (AD-15); its missing implementation is already `NC-9`.
5. **Published artifact authenticity:** current Release and post-release workflows require a non-draft, `immutable == true` GitHub Release, at least one durable asset, and a tag resolving to the exact candidate (`.github/workflows/release.yml:337-403`; `.github/workflows/release-evidence.yml:335-390`; `eng/release_contract.py:276-317`). The 2026-09-09 API sample showed the latest releases as immutable with per-asset SHA-256 digests. NuGet-served packages are independently content-compared and repository-signature verified (`.github/workflows/release-evidence.yml:451-581`).
6. **Fallback design:** AD-9 binds approval to exact candidate blobs, graph, policy, workflow definition, and CI run/attempt; forbids defaulting/rebinding; and fails closed before side effects (`ARCHITECTURE-SPINE.md:202-234`). The problems are the already-registered implementation deviations, not the current AD text.
