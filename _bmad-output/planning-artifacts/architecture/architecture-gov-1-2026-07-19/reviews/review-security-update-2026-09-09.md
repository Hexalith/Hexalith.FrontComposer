## Verdict

**FAIL — no Critical finding, but three High architecture gaps remain.** The candidate/publisher privilege split is now sound in principle: candidate-controlled execution is confined to a secretless/read-only builder, the publisher is candidate-free and environment-protected, artifact coordinates and bytes are authenticated before credential/OIDC/API use, attestation subjects and identities are closed, and every partial external state is classified as an incident. The remaining Highs are evidentiary and authorization-boundary failures: the fallback issuer is self-asserted rather than authenticated; the fallback record itself is not retained, so independent and historical verification has only a digest; and partial-publication evidence has no mandatory durable immutable home.

Counts: **Critical 0 · High 3 · Medium 2 · Low 0**. The lower-severity sweep was time-boxed at the reviewed hash; the report records only definite findings.

## Confirmed security properties

1. **Candidate code is separated from authority.** AD-18/AD-19 give the builder no environment, secret, OIDC, or write permission and move all protected work to pinned, candidate-free owner code in a separate job. The publisher never checks out FrontComposer or executes archive/package/configuration content.
2. **Whole-job credential exposure is treated honestly.** The spine no longer claims step-level token elevation; it requires artifact/archive authentication before the first credential, OIDC, or write-API use and relies on candidate-free closure bytes for the whole protected job.
3. **Attestation acceptance is closed.** The exact `actions/attest` commit, SLSA predicate type, GitHub issuer, repository/caller/reusable/run/environment coordinates, and exact no-extra package subject set are bound. Ordinary network/action/permission/validation failures cannot select fallback while capability is supported.
4. **Archive data is bounded and non-executable.** Raw/member/uncompressed/ratio/path caps, overlap/encryption/ZIP64-consistency checks, fresh-directory extraction, declared regular members, descriptor digests, and destination-name collision checks close the major zip-slip, link, and decompression-amplification paths.
5. **Publication is fail-closed rather than falsely atomic.** The contract serializes by version, rechecks external uniqueness immediately before the first side effect, stages a draft, verifies GitHub assets and NuGet packages, then finalizes once. Any observed external mutation inconsistent with the owner marker is an incident, including failures before the marker can be persisted.
6. **Runtime extensibility is denied.** Protected and post-release code cannot use package managers, installers, generated commands, candidate release configuration/plugins, redirects, or downloaded scripts; executable sources must be literal-commit closure members. SEC-UPD-04 is the narrow platform-action-delivery ambiguity, not a candidate-controlled extension path.
