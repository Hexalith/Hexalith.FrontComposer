## Detail on the High findings

### AU-1 — The ratified A-3 rule cannot be applied inside Hexalith.Builds (AD-13)

AD-13 `:319-324`: "a local `uses:` under `.hexalith/builds-execution/` … resolves into Hexalith.Builds at the single
literal 40-hex `ref:` of the `actions/checkout` step targeting that path in the same workflow blob text; zero or
multiple such refs fail closed." The reusable workflows the closure must traverse do exactly this with a
non-literal ref: `domain-ci.yml:294-303, 320` and `domain-release.yml:290-297, 684-691` check out
`repository: Hexalith/Hexalith.Builds`, `ref: ${{ inputs.builds-execution-sha }}`, `path: .hexalith/builds-execution`
and then `uses: ./.hexalith/builds-execution/Github/initialize-build` (and `dapr-init`, `governed-provenance`,
`publish-containers`).

- **Unit A** (spine-literal): scanning the Builds blob text yields zero literal 40-hex refs → fail closed. No
  `ci`, `release`, or `post_release` row can ever be drafted; the registry in `eng/dependency-graph-policy.json`
  (which lists `Github/initialize-build/action.yml@4eb33928…` etc.) is unexplainable.
- **Unit B** (shipped, `workflow_source_closure.py:489-491`): `if repository == _BUILDS_IDENTITY: target_commit = commit`
  — the ref scan is bypassed and the local action is taken from the enclosing Builds commit.

Both are readings of the same sentence; they produce different action sets and `closure_digest`s, so a C#
Governance re-implementation of the closure and the Python engine cannot both match one policy row. The fix is a
one-sentence carve-out (table). It is sound because AD-13/AD-17 already require the caller's
`builds-execution-sha` input to equal `reusable.commit`, which is precisely the value the expression resolves to.

### AU-2 — Governance pins are enforced off the release path (AD-12/13/17/18)

AD-13 makes "exactly one completed successful push-CI run of `.github/workflows/ci.yml`" the sole release
authority and `release_contract.py:262-263` enforces `path == ".github/workflows/ci.yml"`. Every Governance
control the spine leans on — the `RELEASE_DEFINITION_FILES`/`FALLBACK_INVALIDATION_FILES` fixture (AD-12),
"Governance pins" of manifest v3 (AD-17), and the static permission/environment assertions (AD-18) — runs in
`quality.yml` Gate 2b (`quality.yml:127-135`; `ci.yml:6-9` says so explicitly). `quality.yml` is not consulted by
release, is not in `evaluator_authorizations`, and is not in either definition-file list.

- **Unit A** (shipped): a change that breaks the Governance fixture (e.g., drops `eng/dependency_handoff.py` from
  `FALLBACK_INVALIDATION_FILES`, or grants `actions: write` to a job) merges with `ci.yml` green, and the next
  dispatch publishes. Every AD-12/AD-17/AD-18 "Governance asserts" clause is satisfied by a test that ran and
  failed.
- **Unit B**: release additionally requires `quality.yml` success for the same head, or the assertions are moved
  into `ci.yml`'s `dependency-governance` job so they are inside the handoff's evaluator closure.

Both conform to AD-13's letter. This is a decision, not a wording fix: moving Governance into `ci.yml` changes the
CI evaluator closure and the definition digest; requiring `quality.yml` adds a second authenticated run to
`select-ci` and puts `quality.yml` into both definition lists (it is currently deliberately unpinned — see
memory note "Workflow edits de-authorize the release chain"). Either way the spine must say which.

### AU-3 — `published` is an undefined state with two owners (AD-15)

AD-15 `:365-366` prescribes the *pre-publication* shape (`published=false`, nulls, empty assets) for "failed or
pre-publication attempts" without defining `published`. `release.yml:464-469` computes
`publication_attempted := release-job success || verify-publication success` and sets `published` from it, so a
protected job that ran `nuget push` for three of eight packages and then failed emits the pre-publication shape.
The shipped verifier only avoids missing this because `release_disposition.py:86-88` classifies from the *job
topology* (`release / release` conclusion not skipped) — a rule the spine never states; AD-15 says the verifier
authenticates "run ID/attempt, repository, workflow path, and conclusion" and works from the handoff.

- **Unit A** (spine-literal verifier): reads `published=false` → "failed attempt, recorded" → no NuGet/GitHub
  lookup. The stray packages are discovered only when a later dispatch of the same version fails at the first
