## Verified current

- **Git plumbing relied on by AD-2/AD-7/AD-8** — `git ls-tree -r -z --full-tree`, `git cat-file -s`, `git config --blob`, `git merge-base`: present and unchanged through Git 2.55.0 (release notes 2.54/2.55 reviewed; only `cat-file --batch` gained a `mailmap` subcommand). Local `git version 2.53.0`.
- **Python stdlib controls in AD-5/AD-14** — `json.dumps(ensure_ascii=True, allow_nan=False, sort_keys=True, separators=(',',':'))` and `hashlib.sha256` behave as specified on local 3.14.4; no deprecation in 3.14.5-3.14.7 changelogs. Python 3.14 is in standard support (EOL Oct 2030).
- **Git object format** — all participating repositories report `sha1`; SHA-1 remains supported with no deprecation plan (BreakingChanges doc).
- **RFC 8785 (JCS)** — still the current Informational RFC (Independent Submission stream), not obsoleted; one erratum (EID 7920) only. AD-5's statement "project canonicalization v1, not RFC 8785" is correctly framed: the Python recipe (ASCII-escaped, sorted keys, compact separators) is *not* JCS (JCS forbids `ensure_ascii` escaping of non-ASCII and mandates ECMAScript number serialisation), so calling it project canonicalisation is accurate.
- **GitHub Actions semantics in AD-8** — `github.sha` on `pull_request` is the merge-branch commit (`refs/pull/N/merge`); `github.event.pull_request.base.sha` exists; `github.event.before` on `push` is the prior head and is `0000…` for a new branch (docs "Events that trigger workflows", 2026). `ci.yml` uses exactly these (`PULL_REQUEST_BASE`, `PUSH_BEFORE`).
- **`workflow_run` and `github.event.workflow_run.head_sha`/`id`/`run_attempt`** — still exist; `release-evidence.yml` uses them and, per AD-15, does not derive the live root from `head_sha`/`GITHUB_SHA`.
- **`github.workflow_ref`/`github.workflow_sha` (caller) vs `job.workflow_ref`/`job.workflow_sha` (reusable)** — semantics as assumed (docs + 2026-09-03 changelog); see C-6 for the GHES caveat.
- **Reusable workflows/actions pinned by 40-hex SHA** — still the immutable reference form; `ci.yml`/`release.yml` pin all external `uses:` to full SHAs.
- **`if: always()` finalizers** — still supported; used in `release.yml`, `release-evidence.yml`, `ci.yml`.
- **Actions run/artifact REST APIs** used by `release.yml` (`/actions/workflows/ci.yml/runs?…head_sha=`, `/actions/artifacts/{id}/zip`) — present; artifacts immutable since upload-artifact v4.
- **AD-6 / BUILD-CAT-1** — still accurate: no `catalog_contract_version` marker exists in `references/Hexalith.Builds` (grep returned nothing); DW-1687 open; marker remains nullable provenance only.
- **AD-11 / Story 11.17d** — accurate: `sprint-status.yaml` line 273-276 and the GOV-1 story (line 167, 371) record completion on 2026-08-02 under the one-story waiver; DW-1706 done 2026-08-28; not reopened.
- **AD-16 statement that issue 17 closed 2026-07-20 without acceptance** — accurate as history (DW-1688 evidence); only its "current state" implications are stale (C-1).
- **Resource ceilings (AD-7, AD-13)** — match `eng/dependency-graph-policy.json` `resource_limits` exactly (4096 edges, 64 MiB ls-tree, 1 MiB .gitmodules, 4 MiB catalog, 16384 files, 16 MiB/256 MiB tree, closure depth 16 / 256 sources / 1 MiB / 16 MiB).
