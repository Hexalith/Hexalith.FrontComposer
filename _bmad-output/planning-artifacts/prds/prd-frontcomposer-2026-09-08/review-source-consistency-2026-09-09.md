# Source/Current-Fit Review

## Verdict

The PRD is not currently decision-safe: its stated release-control model and GOV-1 readiness state conflict with the repository that would execute the release. Most referenced artifacts, sprint facts, package identities, and disclosed MCP risks are traceable, but the exact Builds provenance, security-residual disposition, and public diagnostic inventory must also be reconciled before approval.

## Findings

- **[critical]** The claimed sole publication control is not the control the current release caller executes (§0 G-1/G-2, §4 FR-24, §14 D-6) — The PRD says `HEXALITH_RELEASE_PUBLISH_ENABLED` is retired and that protected-production approval plus the pinned exact-SHA workflow is the sole publication path (`_bmad-output/planning-artifacts/prd.md:18`, `:30-31`, `:443-454`, `:656`; `_bmad-output/planning-artifacts/prd-addendum-2026-09-08.md:16`). In contrast, the current caller explicitly leaves `governed-release` unset/false and says FrontComposer stays on the legacy path (`.github/workflows/release.yml:307-329`). The pinned/current reusable workflow defaults that input to false, selects the legacy job, and still gates publication on the repository variable being exactly `true` (`references/Hexalith.Builds/.github/workflows/domain-release.yml:125-133`, `:254-262`, `:401-416`). *Fix:* Rewrite G-1/G-2, FR-24, NFR-12, D-6, and the addendum to describe the actual legacy caller and active deny-by-default variable gate, or first migrate the caller to the governed path and produce evidence that the variable was retired.
- **[critical]** GOV-1 is not merely awaiting sign-off and run IDs (§0 G-2, §9 SM-2a, §14 D-11) — The PRD says no code work is identified and local proof is done (`_bmad-output/planning-artifacts/prd.md:31`, `:589`, `:661`). The current working-tree GOV-1 validation instead records a failed implementation conformance review and 30 open nonconformances, including fallback digest rebinding, authorization soft-defer, post-release authorization mismatch, handoff/ledger omissions, and missing workflow selection (`_bmad-output/planning-artifacts/architecture/architecture-gov-1-2026-07-19/validation-report-2026-09-08.md:15-18`, `:38-43`; `_bmad-output/planning-artifacts/architecture/architecture-gov-1-2026-07-19/nonconformance-register-2026-09-08.md:3-18`, `:28-40`). *Fix:* Make closure of the current implementation nonconformance register part of G-2, remove the “no code work”/“local proof done” claims, and require a passing revalidation before external proof and sign-off can close the gate.
- **[high]** Exact Builds provenance is stale, so G-3 is not approval-only (§0 G-2/G-3, §7, §14 D-11–D-13) — The PRD and addendum identify `references/Hexalith.Builds` as `35c3d1e5…` and describe that exact identity as current (`_bmad-output/planning-artifacts/prd.md:31-32`, `:540`, `:661-663`; `_bmad-output/planning-artifacts/prd-addendum-2026-09-08.md:32-40`). At current root `HEAD`, `git ls-tree HEAD references/Hexalith.Builds` returns `a32cb422749352cce8dec948aa3e78c8f00eb4cf`; the approval contract and captured provider evidence still bind `35c3d1e5…` (`_bmad-output/contracts/frontcomposer-eventstore-approved-runtime-identity-v1.json:8-13`; `_bmad-output/implementation-artifacts/evidence/pact-provider-reconciliation/provider-verification.json:50-66`). EventStore remains `059f6a89…` and the catalog still selects `3.103.0`, but the asserted exact catalog provenance has changed. *Fix:* Either recapture/extend the evidence at `a32cb422…` and update the identity contract/PRD, or explicitly define a semantic-compatibility rule that permits this catalog-only advance; until then G-3 includes local evidence work, not approval alone.
- **[high]** The security residual is both accepted and explicitly not accepted (§4 FR-19, §14 D-14, §15 OI-2) — FR-19 calls the unauthenticated `tools/list` validity oracle an “Accepted” residual (`_bmad-output/planning-artifacts/prd.md:373`), and the addendum similarly calls descriptor disclosure accepted pending confirmation (`_bmad-output/planning-artifacts/prd-addendum-2026-09-08.md:95`). D-14 and OI-2 say those disclosures require dated security sign-off, are not pre-accepted, and that nothing about either oracle is accepted until OI-2 is signed (`_bmad-output/planning-artifacts/prd.md:664`, `:675`). *Fix:* Use one disposition everywhere—“observed residual pending OI-2; not accepted”—or record the actual dated approval and close OI-2 with its evidence.
- **[medium]** The public diagnostic inventory omits stable public IDs and misstates the owned bands (§4 FR-3, §11 Public API and diagnostic inventory) — The PRD reduces the surface to build-time `HFC1001–HFC1070`, migration `HFC0001`, runtime `HFC2xxx`, and tooling `HFCM9xxx` (`_bmad-output/planning-artifacts/prd.md:199`, `:640`). The authoritative registry allocates numeric bands through MCP and Aspire (`docs/diagnostics/diagnostic-registry.json:6-36`) and contains the public MCP ID `HFC4001` plus the approved cross-package public exception `HFC1601` (`docs/diagnostics/diagnostic-registry.json:2505-2528`, `:2531-2543`). *Fix:* Make the registry the referenced executable authority and update the PRD inventory to cover all owned bands and approved exceptions, rather than presenting the partial list as the public surface.
