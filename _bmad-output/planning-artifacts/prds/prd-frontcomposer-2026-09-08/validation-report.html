Poor

This is a substantively strong brownfield PRD: it has a specific product thesis, unusually concrete functional consequences, explicit delivered-versus-gated status, and a serious decision/open-item register. It is not yet safe as the milestone-closure instrument it claims to be, however, because three evidence-gate pass conditions permit closure without evidence or approval that other sections say is required; for this high-stakes chain-top use, the rubric verdict is fair pending gate repair.

The source/current-fit review materially lowers the consolidated grade to Poor. The release-control model conflicts with the workflow that currently executes releases, current GOV-1 validation records 30 open implementation nonconformances despite the PRD saying no code work is identified, exact Builds provenance has drifted, and the security residual has contradictory dispositions. Until those contradictions are reconciled, the PRD is not decision-safe for product re-approval or milestone closure.

Decision-readiness

thin

Section 0.1 identifies one authoritative milestone table, separates evidence gates from approval gates, and assigns each row an owner, artifact, and current state. Section 12 and Addendum §6 expose real trade-offs. The decisive weakness is that the authoritative pass conditions do not consistently encode the evidence and approval obligations stated elsewhere, so a literal gate operator can reach a different result from a reader of the full document.

high

G-2 allows missing proof to satisfy its pass condition

§0.1 G-2
The row accepts either v4.2.0 run IDs or a declaration that proof was not produced, while its state and SM-2a say proof citation remains open.
Fix: Require authenticated run IDs and proof, or a separately owned, dated waiver with explicit residual risk.
high

G-6 can choose a substitute without proving adoption

§0.1 G-6; §12.2 OI-5
Choosing Parties as fallback carries no explicit requirement for evidence equivalent to the dated, candidate-bound Tenants bootstrap proof.
Fix: Require equivalent Parties projection-and-command proof; only a decision to hold may end the decision without closing G-6.
high

G-7 omits mandatory security acceptance

§0.1 G-7; §12 D-14; OI-2
G-7 requires an audit suite, while D-14/OI-2 additionally require dated independent security sign-off for the disclosed oracles.
Fix: Add OI-2 sign-off or the completed gated-list alternative to G-7 and keep that alternative pending until signed.
medium

D-13 is accepted, proposed, and non-gating at once

§12 D-13; §12.1; OI-4
The RC pin posture is called accepted in one place, proposed in another, and is not attached to a gate.
Fix: Record Product's decision, or assign the accepted risk explicitly to Architecture and remove Product confirmation as open.

Source/current-fit review

review-source-consistency-2026-09-09.md

The PRD is not currently decision-safe: its stated release-control model and GOV-1 readiness state conflict with the repository that would execute the release. Most referenced artifacts, sprint facts, package identities, and disclosed MCP risks are traceable, but exact Builds provenance, security-residual disposition, and public diagnostic inventory also require reconciliation.

critical

The claimed publication control is not what the current caller executes

§0 G-1/G-2; FR-24; D-6
The PRD retires the variable gate, but the current caller selects the reusable workflow's legacy path, which still requires HEXALITH_RELEASE_PUBLISH_ENABLED=true.
Fix: Document the active legacy control, or migrate first and capture retirement evidence.
critical

GOV-1 has unresolved implementation nonconformances

§0.1 G-2; SM-2a; D-11
The PRD says no code work is identified and local proof is done, while the current validation records 30 open nonconformances.
Fix: Require register closure and passing revalidation before proof and sign-off can close G-2.
