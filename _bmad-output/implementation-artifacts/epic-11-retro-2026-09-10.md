## Findings

### What landed well

- The main architectural changes are deliberate and traceable: generated command routes now use the approved `/commands/{BoundedContext}/{CommandTypeName}` family; MCP lifecycle state moved to a singleton store behind a scoped facade; Contracts became a UI-clean dual-TFM kernel with a separate `Contracts.UI`; and `ProjectionQuery` owns criteria while the v1.12 flat JSON shape remains compatible. The relevant current contract, route, package, and layering tests pass.
- Stories 11.15 and 11.16 consolidated the explicitly approved storage/snapshot, hydration, JSON, fatal-classification, and generated-literal clusters without falsely claiming every similar mechanism was unified. Focused consolidation tests pass: Shell layering 7/7, fatal-exception governance 2/2, `FcJson` 2/2, hydration 6/6, and generated literals 2/2.
- Story 11.23 activated Recommended analyzers with warnings-as-errors, and the Release solution build is currently clean: zero warnings and zero errors.
- Three real gaps visible at the Epic 11 endpoint were subsequently repaired: fatal fallback-polling hot restart and fatal-failure loss were fixed by `d6154159`, and the generated provider timeout now captures its cancellation token before the CTS can be disposed (`01744176`). Current source and focused tests preserve those repairs.
- Epic 10 follow-through was effective: its four retrospective actions are already `done`, and the corresponding validator, documentation-drift, Testing privacy, and route-decision evidence remains present.

### Blocking findings

1. **Story 11.24 identity/compatibility evidence is not coherent at current HEAD.** `CiGovernanceTests.EventStoreRuntimeIdentitySeparatesCurrentCompatibilityFromHistoricalApproval` expects the current Builds gitlink `35c3d1e5…`, while HEAD records `a32cb422…` (`tests/Hexalith.FrontComposer.Shell.Tests/Governance/CiGovernanceTests.cs:3862`). More fundamentally, the original epic criterion requires successful provider verification and AppHost smoke against the exact approved `bb94d93… / 3.91.1 / a8a50859…` tuple; the frozen story later allowed identity adoption independently of compatibility, and the archived evidence for that approved tuple records provider and smoke failures. The later passing evidence uses a different tuple. This is both a current red governance gate and an unresolved epic-to-story contract deviation.
2. **Story 11.23's analyzer seal is stale.** `AnalyzerPolicy_IdentifierInventory_MatchesSeal` reports 3,327 public test identifiers with SHA-256 `e33cb6e8…`, while the approval ledger seals 3,325 and `36c57e1b…` (`_bmad-output/contracts/analyzer-policy-exception-ledger-v1.json:100-101`; `AnalyzerPolicyGovernanceTests.cs:464`). Recommended activation still builds cleanly, but the declared anti-drift gate does not pass.
3. **Two automated acceptance pins are red.** The Story 11.7 Playwright route test stops before activation because `getByRole('heading', { name: 'Counter' })` matches both the banner and main `<h1>` (`tests/e2e/specs/route-contract.spec.ts:18`); manual activation reaches `/commands/Counter/ConfigureCounterCommand`, so behavior works but its automated proof is broken. The SourceTools FC-NIP document contract also expects stale PRD text such as `Resolved 2026-08-12`, causing `SharedManifest_WhenApplied_PinsDocumentsAndExactTables` to fail (`tests/contract-fixtures/fc-nip-command-target-identity-contract.json:146-149`; `FcNipCommandTargetIdentityContractTests.cs:24`).

### Current cross-boundary risks

- The review lenses independently found that `ProjectionFallbackRefreshScheduler` treats a no-ETag response as unchanged when row count and total count are unchanged, even if row values differ, and retains the first lane when a `ViewKey` is re-registered with a changed tenant/query (`ProjectionFallbackRefreshScheduler.cs:48-64,289-312,449-453`). Both paths can leave a grid displaying stale or wrong-scope data and need deterministic regression coverage.
- Lifecycle identifiers are not fully consistent across packages. `TestCommandService` emits `test-message-0001`/`test-correlation-0001` although `CommandResult` documents ULIDs and Shell consumers validate them; MCP's regex accepts 26-character Crockford strings beginning with `8`–`Z`, which overflow canonical ULID range (`TestCommandService.cs:64-69`; `FrontComposerMcpLifecycleStore.cs:159-179,296-297`). Testing evidence serialization can also turn a configured fake outcome into a serializer exception, and its sensitive-key list covers only `token`, `secret`, and `password`, not common credential fields such as `Authorization`, `ApiKey`, `Cookie`, `PrivateKey`, or `ConnectionString` (`Evidence.cs:51-130`).
- The operator correlation contract remains split. `ScopeReadinessStorageReadyDispatched` passes short correlation IDs through `Bounded` unchanged, while lifecycle/HotPath events always use `sha256:<16 hex>`; Diagnostic and HotPath digest helpers also produce different formats. These are already tracked as open, implementation-approved DW-1769 and DW-1770 (`deferred-work.md:8596-8614`) and should not be duplicated as new debt.
