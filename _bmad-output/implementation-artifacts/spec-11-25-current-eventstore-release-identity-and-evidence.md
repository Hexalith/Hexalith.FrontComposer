## Design Notes

Use a new `.v2` schema rather than expanding v1. Keep the live path as CI's recapture target and move the old packet once to a hash-pinned archive. Evidence validity and migration approval remain separate states.

The active evidence contains a deterministic `frontcomposer-runtime-inputs.json` manifest over a validator-owned fixed scope: `src/**`, the directly executed `samples/Counter/**` tree, root build/package/toolchain inputs, the canonical Pact/manifest/provider-state inputs, and every root gitlink selected by the AppHost's source build graph (Builds, EventStore, Tenants, Parties, Memories, Commons, and PolymorphicSerializations). It records the capture revision and exact bytes/gitlink values. Generation and validation reject relevant untracked files, symlinks, or any working-tree/index difference from the manifest. Later governance-only commits may validate only while recomputation yields the identical manifest; never overwrite observed HEAD to manufacture equality. Mark every hash-bound LF artifact, including the course-correction proposal, `-text` so checkout cannot rewrite its bytes.

Treat Git index acceleration flags and build discovery as adversarial inputs, not cleanliness evidence: reject `assume-unchanged` and `skip-worktree` inside the scope, establish that every hashed worktree file is the indexed/HEAD input even when ordinary `git diff` would skip it, include `Directory.Build.rsp`, and reject recognized root build-control files that are ignored, untracked, or outside the declared inventory. Manifest generation is an atomic compare-and-replace operation only after all checks pass. Before `aspire start --no-build`, clean/rebuild or isolate every executable output so stale ignored `bin`/`obj` content cannot participate.

Never execute a caller-configured Git clean/smudge filter to establish byte identity. Read raw worktree and index bytes, then allow only validator-owned text/EOL equivalence selected by tracked repository attributes under a sanitized Git attribute/config environment; any effective `filter`, `ident`, working-tree encoding, repository-local info attribute, or global/system attribute source fails closed. Enumerate untracked symlinks before output filtering, so a project-adjacent `bin`/`obj` link cannot redirect build writes outside the sealed checkout.

Use a sibling-relative `provider-verification.json` coordinate in the run receipt so the same bounded schema resolves correctly in the live and sealed directories, and resolve live, sealed, and historical roots from identity-owned canonical paths rather than accepting detached caller substitutions. The manifest must predate both evidence lanes; record and validate explicit provider and AppHost completion timestamps before the recapture decision; require the decision to precede the final approval-subject freeze, each transfer subject to postdate its policy, final receipts to postdate that freeze, and every live or sealed timestamp to be no later than current UTC plus a small documented clock-skew allowance. Reject duplicate named hashes and all recursive undeclared evidence/archive entries, including empty directories.

The approval policy is hash-bound before the final subject freeze and maps each role/actor to exact permitted durable-source coordinates; empty current assignments are valid only while approval is open. Those assignments must also equal a validator-owned authority bootstrap that is not supplied by the evidence packet. Story 11.25 ships that bootstrap empty: approval remains open, and a later human-approved code change must pin exact actor/role/source assignments before receipts can authorize migration. The final subject binds the policy hash, effective roster hash, effective required roles, OI-18 decision/hash or explicit absence, active tuple, runtime-input manifest, decision, and evidence. Receipt validation uses exact JSON types and the bound actor/role/source mapping plus a parsed HTTPS URL with a host.

The default effective roles are EventStore maintainer, FrontComposer maintainer, and Release Owner. The OI-18 alternative has its own pre-frozen transfer subject and separate Product/Architecture actor/source assignments and receipts. Only after both valid transfer receipts exist may the final subject remove `eventstore-maintainer`, add the explicitly named accountable FrontComposer replacement role, and freeze; the replacement-role migration receipt must postdate the completed transfer. Never satisfy transfer by assigning a FrontComposer actor to the EventStore role.

All credential and bearer-token destinations must parse as loopback, and credential-bearing HTTP clients must reject every redirect rather than validating only its first hop. One absolute monotonic deadline covers readiness, connect, TLS, upgrade, headers, bodies, WebSocket frames, and cleanup; no phase may reset it, and enough cleanup budget must be reserved to confirm both process and listener termination. Failed readiness returns before command mutation. Treat health/liveness only as application readiness; prove authentication separately with credential-specific anonymous and invalid-token rejection before authenticated command, command-status, tenant-bound query, and SignalR success. Record exactly the described ten-resource set and exact typed semantics for all five observations and four controls; never substitute a hard-coded topology for the actual describe result.

Disable environment proxies for all credential-bearing requests. Bound each operation by the smaller of its phase deadline and the run deadline. A cold start proceeds only after both the stop command and Aspire state confirm absence. Classify generated Dapr/auth support records through stable describe metadata and their parent relationship rather than a name pattern. Require the tenant-handler query to report `HandlerComputed`. Pair SignalR rejection and success on the same candidate URL, validate the complete HTTP upgrade including `Sec-WebSocket-Accept`, parse and reassemble bounded WebSocket frames, and reject malformed or oversized traffic. Record the configured timeout in the AppHost artifact and validate elapsed time against it. If no endpoint URL was ever discovered, cleanup may report ports closed only when evidence proves no host was started; otherwise it fails closed.

Treat the build command and dependency checkouts as part of provenance, not merely launch mechanics. Provider verification must execute only after its prior output and report are removed and a clean, single-node, non-incremental build succeeds. AppHost clean/build must pin every source-selection global property, record the intentional restore-policy overrides, and validate the evaluated project graph resolves only the root-declared checkouts. Each source-built dependency must be a real directory at its indexed gitlink with no hidden index flags, byte drift, untracked build input, or initialized nested submodule. Active validation accepts only the repository's canonical Pact directory.

The provider lane creates its runtime-input manifest before cleaning, restoring, building, or executing provider code and carries that exact document through receipt creation and final validation. Receipt generation is not a summary-field signer: it first applies the same canonical Pact, provenance, interaction, timing, redaction, and report-shape checks used by the final gate. The fixed identity path is `repository_root/_bmad-output/contracts/frontcomposer-eventstore-approved-runtime-identity-v2.json`; all active, history, and Pact roots derive from `repository_root`, never from a caller-selected identity parent. A symlinked dependency checkout root or any symlink selected by the sealed restore/build/runtime graph is not source-equivalent. The only inert tracked exceptions are the three human-approved links already present in the pinned tuple: the EventStore architecture spine and Commons `.clinerules`/`.cursorrules`; validator-owned dependency, path, and symlink-blob identities bind those exceptions exactly, so same-looking documentation or tooling links remain rejected.

Fresh output means fresh restore intermediates as well as assemblies. Use an isolated intermediate/output root or remove and regenerate the selected graph's `bin`/`obj` state with a forced restore before the no-incremental build. Query evaluated imports and execution-relevant `ProjectReference`, `PackageReference`, `Reference`/`HintPath`, analyzer, additional-file, content/copy, and native/runtime-copy items, then traverse every resolved assets graph. Each selected path must resolve beneath a sealed repository input, the fresh sealed package root, or the selected SDK installation. Recheck the deterministic evaluated binding after build and inspect the produced `.deps.json` plus runtime output inventory so target-generated or shadow managed/native binaries cannot evade it. The resulting source graph reaches exactly EventStore, Tenants, Parties, Memories, and Commons from their guarded root checkouts. Builds remains a sealed build-control input and PolymorphicSerializations remains sealed and source-pinned but inactive; scalar `*FromSource` properties alone are supporting evidence, not the verdict.

Restore provenance uses a distinct fresh, non-symlinked `NUGET_PACKAGES` root outside the repository for each provider and AppHost lane. No ambient or pre-populated global package content is eligible. After forced restore and before the first post-restore MSBuild evaluation, build, or start operation, derive a deterministic ledger from every expected assets graph. Provider assets are the two declared graphs. AppHost assets are discovered without running MSBuild by JSON-only traversal from the restored AppHost `project.assets.json`; the subsequent evaluated source graph must select exactly that set. Bind each graph's path/hash and exact package set; require their union to equal the global package set; validate the NuGet content hash as Base64 SHA-512; recompute it from the selected `.nupkg`; and bind a sorted extracted-tree inventory containing each regular file's relative path, size, and SHA-256 while rejecting symlinks and non-regular entries. Recompute the identical ledger after execution before success, using the original capture timestamp only for comparison. Provider receipt, AppHost evidence, and final validation carry that ledger; a missing graph, orphan package, archive/extracted-byte change, package-root mutation, or ledger drift fails closed.

The new AppHost schema records `executionStartedAt` immediately before its first post-restore build command. Independent validation requires the runtime manifest to predate the package ledger, the ledger to predate `executionStartedAt`, and that boundary to precede completion. Newly generated schemas cannot omit these bindings. The frozen package-less AppHost v2 packet remains accepted only because its whole artifact is already hash-bound by the preserved active identity; it does not serve as proof for a new capture.

Treat health as readiness unless an invalid-bearer control is executed against that same health endpoint. Before sending credentials, normalize `localhost` candidates to numeric loopback and verify the actual connected peer remains loopback; hostname spelling is insufficient. HTTP error bodies use the same absolute deadline and size bound as success bodies, catch their own read failures, and return a deterministic failed control instead of escaping capture. Redaction recognizes quoted JSON secret keys and all credential-bearing cookie keys without relying on equals-only fragments. Upload only paths validated by the current invocation, and keep repeated mutation tests from rehashing the immutable real dependency graph so Gate 2c remains comfortably inside 45 minutes.

Only `/health` establishes the readiness observation; `/alive` may be recorded separately as liveness but never satisfies or labels readiness. Numeric-loopback resolution receives the already-established absolute deadline and runs behind a bounded resolver boundary that cannot keep the process alive or send credentials after timeout. Approval actors are canonical lower-case coordinates mapped by validator-owned code to immutable principals; role separation compares principals, so case variants or cross-coordinate aliases cannot satisfy distinct-role requirements. Story 11.25 leaves both actor authority and principal maps empty.

Preflight ownership is explicit: if the sealed runtime scope is dirty, capture writes failure evidence without stopping a host it did not start. On a clean run, capture records that the local SQLite name-resolution files were absent, performs its cold-stop/start lifecycle, then removes only the `nr.db*` files created by that invocation after process and listener termination; success requires recomputing the runtime scope clean. Aspire state output must contain one authoritative JSON value. Every bearer-authenticated surface is paired with an invalid-bearer rejection; command correlation equals the submitted ULID and query header/body provenance cannot conflict. SignalR first obtains a connection coordinate through a separate valid negotiation, then attempts the actual `/hubs/projection-changes` WebSocket upgrade with an invalid bearer and requires HTTP 401/403 before any `101`; authenticated success uses a fresh valid negotiation and a separate standards-valid upgrade on that same hub path, with no preemptive acknowledgement. Live validation pins the full ULID, exact indices, nested timing containment, and empty approval-binding fields. Manifest temporary files are created with exclusive no-follow semantics, and boundary tests cover each declared network-size limit and header/frame deadline. Redaction exemptions are exact schema-known fields/values rather than substring classes, each Authorization occurrence is classified separately, and the Python and PowerShell scanners share the same secret-key and Base64url grammar.
